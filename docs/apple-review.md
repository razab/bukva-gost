# Проверка перед Apple Review

Основной запуск в Codex: **`$apple-preflight`**. Skill читает факты локального
скрипта, применяет pinned `app-store-review` от safaiyeh и сверяет применимые
пункты с текущей документацией Apple. AI-аудит идёт в текущей сессии Codex;
дочерняя модель, внешний AI API и ключи для него не запускаются.
Установленные проектные skills доступны со следующего пользовательского хода;
в сессии установки их инструкции можно прочитать напрямую.

Для технической части из терминала:

```sh
npm run check:apple
```

Нужны Node>=20 и уже подготовленный `dist/web/`. Команда его не пересобирает.
Если комплект отсутствует/устарел, сначала отдельно решить, нужен ли новый:
`npm run package:internal`. Это отдельная команда со своими выходными файлами.

Проверяются whitelist/хеши, совпадение байтов с текущими исходниками и общей
offline-обёрткой HTML, наличие известной dev-панели, pinned checklist/MIT,
сведения о происхождении ASCON/PNG. Подпись, SDK, privacy manifest и store-поля
не определяются из веб-комплекта. Отсутствие доказательства прав даёт UNKNOWN,
наличие dev-панели — FLAG; это не автоматическое обвинение в нарушении Apple.

## Результат

Новый каталог `reports/apple-review/<run-id>/` содержит:

- `mechanical.json` — факты скрипта, build/version, Git HEAD, входные SHA-256,
  fingerprint и версия checklist;
- `report.json` / `report.md` — общий результат; после одного скрипта AI-разделы
  явно NOT_CHECKED;
- `semantic.json` — результат агента после полноценного вызова skill.

Статусы: PASS конкретного факта, BLOCK, FLAG, UNKNOWN, NOT_CHECKED, N/A.
Сводка сохраняет подпись/устройство/App Store Connect как непроведённые и не
называет приложение одобренным. Source review не доказывает фактическую сетевую
трассу или аппаратное поведение. Неприменимые покупки/аккаунты не предлагается
добавлять для прохождения checklist.

Коды завершения:0 — доступные механические проверки закончены без BLOCK;
1 — найден BLOCK;2 — ошибка или отсутствующий обязательный вход. Exit0 не
означает завершённый AI-аудит или готовность к отправке. Вся неполнота видна
в отчёте отдельно.

Для явно названного нового каталога и завершения отчёта агентом:

```sh
npm run check:apple -- --report-dir reports/apple-review/my-run
npm run check:apple -- --finalize reports/apple-review/my-run
```

Перед finalize агент заполняет `semantic.json` по
[формату](../.agents/skills/apple-preflight/references/report.md). Валидатор
проверяет статусы, обязательные разделы, ссылки на входы/строки и сохранность
механических фактов. Он не доказывает истинность смыслового вывода модели.
После изменения входов нужен новый запуск. После прерывания можно дополнить
прежний semantic.json и повторить finalize при неизменном fingerprint.
Существующий каталог не перезаписывается новым стартом. Отчёты не пишутся
за пределами `reports/apple-review/` и не включаются в LAN/offline-приложение.

## Источники и границы

Поставлен safaiyeh/app-store-review-skill1.5.0, commit
`7197cff003728b660542b37d6b6d0167fe2ec1ed`, MIT. Опись:
[upstream.json](../.agents/skills/apple-preflight/references/upstream.json).
Удалён только лишний forwarding SKILL.md, чтобы остался один вход.
Внешний checklist не обновляется автоматически; его хеши проверяются до
применения. Форма отчёта учитывает подход chingiz/appstore-preflight;
его Xcode-скрипты и третий пересекающийся пакет не установлены.

Найденное расширительное «WebView будет отклонён» сверяется с фактическим
[§4.2 Apple](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality).
Не добавлять случайные native-функции ради checklist. Аналогично, требования к
privacy manifests устанавливаются по реальным API/SDK, а не наличию имени файла.

Аудит не исправляет продукт, не подключается к App Store Connect, не отправляет
feedback и не публикует приложение. Обнаруженные изменения предлагаются через
OpenSpec отдельно. Нативная упаковка, права и аппаратный пилот остаются
[условиями выпуска](release-readiness.md).

Регрессии входят в существующий offline-bundle, следовательно в medium и full:
порча/устаревание/отсутствие комплекта, подмена checklist, реальные CLI exit-коды,
symlink-точка входа, повтор/восстановление, ложный PASS/источник/строка, защита
технических фактов и stale fingerprint. Нативный PASS на fixture не моделируется.
