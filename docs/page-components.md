# Компоненты страницы буквы

Текущий учебный порядок и этапы — в разделе «Курс из предоставленной прописи, сборка21» в конце документа. Старые разделы описывают историю контрактов.

Сборка 15 расширила набор до 33 букв в обоих регистрах. Для каждой страницы предлагаются только части её собственных траекторий. Ниже первоначальный контракт А/а сохраняется как частный случай.

Текущая точка входа — `concepts/index.html`. В разделе «Состав страницы» можно выбрать рисунок для дорисовки и включить тренировочные элементы с 3, 4 или 5 пробами каждого типа. По умолчанию пять частей по четыре пробы: горизонталь и две наклонные из А, корпус с прямыми сторонами и стойка с выходом вправо из а. Посторонние для текущих букв формы в редакторе не предлагаются. Арбуз — отдельная иллюстрация слова и не связан с выбором задания.

## Файлы и ответственность

- `concepts/components/catalog.js`: 40 готовых SVG-заданий и пять частей текущих А/а. `setLetterSources` получает настоящие учебные траектории из index.html; `elementsFor` фильтрует части по буквам.
- `picture-exercise.js`: компонент рисунка. Подключает выбранную SVG-геометрию к отдельной поверхности, её хранилищу и сбросу.
- `curriculum.js`: учебный порядок и ограничения по уже введённым буквам, независимо от доступности контуров.
- `row-ruling.js`: горизонтальные направляющие по всей ширине строки, измерение переноса и очистка наблюдателей.
- `practice-element.js`: компонент строки повторов одного элемента и общая ячейка письма. Использует ту же поверхность, размер, bold, допуск, оценку и скрытый сброс, что и буквы.
- `page-composition.js`: проверка состава, хранение и панель выбора. Состав отделён от черновиков рисунков.
- `index.html`: сборка страницы, общий ввод, настройки, оценка и показ букв.

Скрипты обычные, не ES-модули: они загружаются локально даже при открытии `file://`, без сервера, CDN и запросов к сети.

## Контракт рисунка

```js
{
  id: 'art-house',
  name: 'Домик',
  fixed: 'M...', // сплошные линии
  trace: 'M...', // пунктирные линии для ребёнка
  decor: '', // незавершённые контуры не заполняются цветом
  completionFraction: 0.797384 // измеренная доля длины; зависит от рисунка
}
```

Система координат — 200 × 200. Начиная со сборки 12 готовые части — связные группы целых штрихов. На дорисовку остаётся минимум 70% уникального контура; фиксированного процента каждого отдельного штриха больше нет. Независимая растровая проверка подтверждает минимум 70% незавершённого уникального контура с учётом наложений. Исходный каталог сохранён в references/picture-catalog-source.json; scripts/prepare-picture-traces.py воспроизводит локальные данные без зависимости от Python в приложении. `WorksheetCatalog.renderPicture()` используется и миниатюрой, и самим компонентом. SVG-строки — доверенные данные каталога, не пользовательский HTML. Компонент выбирается только по известному ID.

`PictureExercise.mount({definition,svg,canvas,resetButton,setupSurface})` возвращает поверхность с `render`, `closeReset`, `destroy`. Приложение уничтожает прежние обработчики при смене компонента. Для каждого рисунка отдельный ключ черновика: `art-kite`, `art-house` и т.д. Выбор другого рисунка не удаляет прежние линии.

## Контракт тренировочного элемента

```js
{
  id: 'gost-b90-a-body',
  name: 'а · Контур с прямыми сторонами',
  letters: ['а'],
  sourceStroke: 0,
  model: [lowercase[0]] // та же траектория, что у буквы
}
```

Система координат — 150 × 180. `model` — массив физических движений, каждое — массив точек. Доступны: gost-b90-A-bar, gost-b90-A-rise, gost-b90-A-fall, gost-b90-a-body, gost-b90-a-stem. Наклонные — точные срезы одного движения А. Части а используют её полные отдельные движения; овал/дуга/произвольная вертикаль исключены. Верхний правый угол корпуса не скругляется геометрией модели.

`PracticeElement.mount({root,definition,repeats,addCell})` создаёт строку из 3–5 независимых проб. `createCell()` подключает одну ячейку к общему механизму ввода. Все элементы, одиночные буквы и последовательности используют одну геометрическую оценку без проверки порядка, направления или отрывов пера. Масштаб полей одинаков с буквами.

## Состав страницы для редактора

Состав — данные, а не условия внутри рендера страницы:

```json
{
  "picture": "art-house",
  "elementsVersion": 2,
  "elements": [
    {"component": "gost-b90-a-body", "repeats": 4},
    {"component": "gost-b90-A-bar", "repeats": 3},
    {"component": "gost-b90-A-rise", "repeats": 5}
  ]
}
```

`PageComposition.get(variant)` возвращает копию состава; `update(variant, patch)` проверяет и сохраняет изменения. Состав хранится в `letter-page-composition-v1` как `{version:1, variants:{...}}`. Каждый из пяти вариантов страницы имеет собственный выбор. Для будущего редактора конфигурацию можно формировать через этот же контракт; полноценного редактора всех страниц алфавита пока нет.

Неизвестные ID исключаются, повторы ограничены значениями 3/4/5, дубли типов не допускаются. Пустой список элементов разрешён. При ошибке localStorage изменения остаются в памяти текущей вкладки и показывается сообщение.

## Черновики и совместимость

Снижение числа проб с пяти до трёх скрывает лишние пробы, а не стирает их. Возвращение пяти восстанавливает рисунки. Отключение типа работает так же. Части из шрифта имеют новые ID `element-v1-gost-b90-<part>-<index>`: старые записи не накладываются на изменившуюся форму. При миграции состава без elementsVersion:2 горизонталь и наклонные заменяются соответствующими частями А с сохранением количества; исключённые части А остаются исключёнными. Добавляются два новых элемента а. Посторонние типы убираются из состава; их черновики warmup-0…5 и element-v1-oval-* и т.д. сохраняются в данных. В новом составе даже полностью пустой набор допустим и сохраняется без автоматического возврата элементов. Предыдущая монолитная версия сохранена в `concepts/previous-before-components.html`.

Общий размер, bold и допуск остаются в отдельном ключе настроек. Проценты и кнопки не входят в canvas. Сброс появляется под процентом отдельной всплывающей кнопкой и не задаёт минимальную ширину поля. Выбор рисунка или изменение состава не очищают историю отмены.

## Последовательность после отдельных букв

`components/letter-sequence.js` — компонент нескольких букв в одном поле. По умолчанию после двух строк отдельных А/а находятся три пробы «ААА». В «Составе страницы → После отдельных букв» можно создать до 12 редактируемых строк; каждая включает текст из А/а/пробелов (до 24 символов), 1–5 повторов и собственный переключатель. При выключении или смене текста прежние записи сохраняются.

Конфигурация дополнена полем:

```json
{"sequence":{"text":"ААА","repeats":3}}
```

`sequence:null` выключает блок. В старых сохранённых составах без этого поля добавляется блок по умолчанию. Пробы имеют собственные ID вида sequence-v1-410-410-410-0; они не подменяют одиночные буквы.

`LetterSequence.compose(text, sources)` принимает реестр символов с моделью и advance, объединяет смещённые траектории и вычисляет ширину поля. Контуры каждого символа берутся из настоящего шрифта через fontOutline. Используются advance выбранного TTF: А=1260/1400*100=90, а=980/1400*100=70. Поэтому масштаб букв совпадает с одиночными пробами, а расстояние соответствует метрикам шрифта.

Общий ввод и оценка теперь принимают размеры системы координат конкретного поля. Система хранения трёх А остаётся 330 × 180, одиночной буквы — 150 × 180. Видимое поле обрезано по геометрии, не растянуто до этих размеров. Нормализованные рисунки преобразуются в исходную систему, а допуск задаётся в экранных px и переводится по фактической ширине видимого viewport. Одна оценка и один сброс относятся ко всей тройке. Порядок/направление штрихов и отрывы не проверяются.

Основа подходит для будущих слогов и коротких фраз через реестр символов, но сейчас доступны только А и а. Неизвестные символы не заменяются системным шрифтом: для них сначала потребуются настоящий контур и учебная траектория.

Проверены точная тройка (100%), незавершённые две буквы, раздельные стороны всех трёх А, сохранение/повторное открытие, сброс целой тройки, смена регистра, количество проб 2/3 и отказ при неизвестном символе. Вид образца отрисован отдельно в assets/letter-sequence-preview.png; полная браузерная раскладка не проверена.

## Правило релевантности и следующий алфавит

Каталог упражнений привязан к текущим буквам, а не предлагает общий список фигур. Исключение элемента — выбор автора страницы; добавление постороннего элемента запрещено проверкой состава. Для следующей буквы сначала извлекается и проверяется настоящий контур выбранного TTF, затем выделяются характерные движения и при необходимости связываются с уже известными частями. У строчной д выбранного ASCON GOST B действительно есть сходный корпус с прямыми сторонами (внутренний контур начинается M700 840H420...), но её верхнее продолжение отличается от а; это наблюдение по исходному TTF, а не готовый урок д.

Превью актуальных пяти частей: concepts/assets/letter-parts-preview.png. Тесты проверяют точное равенство упражнений исходным траекториям, фильтрацию по буквам, миграцию и сохранение отключений.

## Компактные поля и общая геометрическая оценка (сборка 06)

`PracticeElement.frame(model, preferences)` вычисляет границы всех точек и запас под текущий допуск/толщину; минимум поля — 48 × 44 CSS px. CSS-ширина/высота = размер viewport × size/100. SVG viewBox и преобразование canvas используют один viewport. Рисунок, показ буквы и сохранённые линии не масштабируются дополнительно. Разлиновка выводится в координатах геометрии, а не на фиксированных 25%/75% высоты коробки.

Нормализованные данные по-прежнему принадлежат старой системе хранения. Pointer переводится из CSS в viewport, затем в эту систему; при выводе — обратное преобразование. Сохранённые пробы и их ID остаются на месте. Прежние заведомо лишние линии за новым viewport могут быть обрезаны визуально, но сохраняются и участвуют в оценке.

`evaluate(strokes, model, tolerance, {width,height})` — одна общая функция без режима ordered. Метрика учитывает покрытие эталона, лишние линии, расстояние и объём введённых линий. Она не присваивает пользовательский штрих определённой букве или номеру движения, не проверяет непрерывность пера и не содержит правил для А/ААА. Отрывы действительно оставляют геометрические разрывы; линия, соединяющая отдельные буквы через пустое место, содержит лишнюю геометрию. Это оценивается общим способом. Показ написания сохраняет прежнюю последовательность.

Проверки включают смену порядка/направления всех штрихов и разбиение каждой траектории на отдельные сегменты для ААА/ааа/АаА/Ааа (100%), незнакомую функции фигуру, низкий процент за горизонталь под буквами, старые данные, точное преобразование pointer и 54 сочетания size/bold/tolerance. `field-render.test.cjs` растеризует 24 поля при крайних и обычных настройках; контуры/допуски не обрезаются. Статическое превью — concepts/assets/compact-fields-preview.png. Эти проверки не заменяют измерение раскладки в браузере/iPad.

Сборка 07: горизонтальный запас — максимум радиуса допуска и половины толщины плюс 2 CSS px. Ширина не меньше 48 px под процент; вертикальный расчёт прежний. Резерв 84 px под пару «процент + сброс» удалён.


## Настраиваемый межбуквенный просвет (сборка 08)

Настройка «Между буквами в слове» — letterGap, 0–50% номинальной высоты заглавной h. Значение 20 означает просвет 0,2h; новая установка и «По умолчанию» используют 20. Отдельное крайнее положение -1, «Из шрифта», сохраняет прежние advance; начиная со сборки 09 старые настройки без letterGap и прежний автоматический режим -1 однократно переходят на 20%; черновики прежних метрик сохраняются. Это не columnGap между независимыми пробами.

`LetterSequence.compose(text,sources,{gap=null,bold=100})`: gap=null сохраняет прежние метрики, числовой gap задаёт расстояние между краями соседних глифов. Sources содержат реальные горизонтальные bounds извлечённых TTF-контуров в координатах листа: А — 148…1130, а — 140…981 шрифтовых единиц, преобразованные тем же fontScale и смещением. Новый origin = предыдущий origin + previous.right - next.left + gap + boldExpansion. Последний член компенсирует добавочную визуальную обводку с обеих сторон. Увеличение размера масштабирует и буквы, и просвет; изменение bold сохраняет заданный чистый просвет. Это явный одинаковый интервал; автоматических исключений/кернинга пар здесь пока нет.

При числовом gap черновик использует ключ sequence-v2-gap<gap>-b<bold>-<text-code>-<trial>. Чужие геометрии не накладываются друг на друга; возврат интервала/толщины возвращает прежнюю запись. Режим «Из шрифта» использует прежний sequence-v1. Старые данные не удаляются. Вычисленная общая модель управляет показом подсказок, размером, вводом и оценкой.

Проверен сквозной сценарий: старая запись → интервал 20 → новая запись 100% → интервал 50 → возврат 20 → повторное открытие → возврат к метрикам шрифта. Дополнительно проверены точные просветы 0/10/20/50 на ААА/ааа/АаА/Ааа и bold 100/150, сохранение масштаба одиночных букв, новые и старые настройки. Растровая проверка расширена до 48 полей, включая нулевой и максимальный интервал.


## Единый дефолт ГОСТ (сборка 09)

20% номинальной высоты заглавной — дефолт и для новой установки, и при обновлении старых настроек. Однократная миграция помечается letterGapDefaultVersion:1 в JSON настроек; метаданные не становятся отдельным контролом. При миграции отсутствующий интервал/прежнее -1 заменяются на 20, числовой пользовательский выбор 0…50 сохраняется. После миграции явно выбранное «Из шрифта» также сохраняется и не сбрасывается при следующем открытии. Кнопка «По умолчанию» возвращает 20. Подпись уточнена: «% высоты заглавной». Формула геометрии и ключи черновиков не менялись.


## Числовая шкала (сборка 10, заменяет поведение -1 выше)

UI и preferenceLimits для letterGap теперь только 0…50. Отметка 20% подписана «по умолчанию» под ползунком на позиции 40% шкалы; дополнительно указан datalist option value=20. Специальный режим -1 удалён из UI и mount. Старое отрицательное значение в хранилище заменяется на 20 независимо от предыдущего маркера; нулевое числовое значение не мигрирует и не заменяется дефолтом. Все новые записи настроек помечаются letterGapDefaultVersion:2. Низкоуровневый compose(...,{gap:null}) оставлен для чтения прежней геометрии в коде/тестах, но регулятор этот режим не вызывает. Прежние sequence-v1 не стираются.


## Редактируемые строки и меньший размер (сборка 11)

Размер теперь 30–160 CSS px номинальной высоты заглавной. Общий масштаб, viewport, допуск и сохранённые координаты работают тем же способом; минимальные размеры для касания и кнопок прежние.

Канонический состав дополнен массивом:

```json
{
  "textRows": [
    {"id":"primary","text":"ААА","repeats":3,"enabled":true},
    {"id":"row-1","text":"Аа АА","repeats":1,"enabled":true}
  ],
  "nextTextRowId": 2
}
```

В редакторе есть «Добавить строку», ввод текста, 1–5 повторов, включение и удаление. Ввод применяется по Enter или завершению редактирования. Неподдерживаемый текст даёт видимую ошибку и не заменяет рабочую геометрию. `normalizeText` допускает только текущие А/а/пробел, приводит латинские A/a к кириллице, удаляет краевые и повторные пробелы. Это редактор текущего урока А/а; остальных траекторий пока нет, системный шрифт не подставляется.

Старое поле sequence мигрирует в строку id=primary с прежними текстом/повторами/включением и прежними ключами черновиков. Поле sequence остаётся зеркалом первой строки для совместимости. Пустой textRows означает отсутствие строк. Остальные строки имеют префикс text-<row-id>- у ключа пробы, поэтому даже одинаковый текст не делит один черновик. ID выдаются монотонным nextTextRowId и не переиспользуются после удаления. Отключение сохраняет текст/повторы; удаление не стирает введённые линии из данных.

В compose пробел не рисует глиф: следующий глиф получает чистый просвет 0,6h (60 единиц), с компенсацией bold так же, как для letterGap. Межбуквенный ползунок не подменяет пробел. Межсловный просвет проверен по реальным контурам обоих регистров.

Сквозная проверка: добавить строку → ввести латинское Aa AA → нормализовать Аа АА → написать → получить 100% → выбрать пять повторов → открыть заново → выключить/включить → удалить без потери данных → добавить новую строку с другим ID. Проверены ошибочный текст, дубли и нулевой набор, изоляция одинакового текста. Растровый тест расширен до 64 полей, включая размер 30 с допусками 2/16. Общая геометрия проверяется в 72 сочетаниях размера/толщины/допуска. Это не проверка реального браузерного редактора или Pencil.


## Цельная готовая часть (сборка 12)

Старый генератор делил каждый контур по длине на 22%/78%. Это создавало рассыпанные куски и заставляло останавливаться внутри линии. Такой подход удалён.

Генератор сохраняет исходные концы SVG-команд, объединяет гладко продолжающиеся кривые и коллинеарные линии в целые учебные штрихи. Окружность не разрезается на произвольные проценты. Затем выбирается одна геометрически связная группа штрихов с бюджетом до 25% общей длины; остальные целые штрихи становятся пунктирными. Если целый штрих не помещается в бюджет, генерация должна остановиться для ручного решения, а не дробить его. Связность допускает зазор до 1,5 единицы 200 × 200 там, где исходные линии почти соприкасаются; далёкие группы готовых штрихов не допускаются. Повторяющиеся полные штрихи убираются до выбора группы. Готовые линии выводятся поверх пунктирных на стыках.

План всех целых штрихов и их назначения сохранён отдельно в references/picture-stroke-plan.json. Растровый тест независимо проверяет минимум 70% уникальной незавершённой геометрии с учётом наложений, полное назначение каждого штриха и одну связную готовую группу. Новый каталог оставляет 75–95% по суммарной длине штрихов (точный процент не фиксирован). Существующие ID и координаты рисунков сохранены: меняется только назначение линий, а не положение введённых записей.

До полной генерации пройден canary на змее и домике: генерация → растеризация/визуальный просмотр → связность/70% → выбор → ввод → переключение → повторное открытие. После этого обновлены все 40 рисунков и коллаж picture-catalog-preview.png. Браузерная раскладка и Pencil не проверены.


## Горизонтальная разлиновка (сборка 13)

`RowRuling` отделяет направляющие от контуров/оценки. Единственный источник номинальных уровней — GOST: baseline=140, верх заглавной=140−100=40, верх строчной=140−70=70. В компактном viewport отображаются только попадающие в него уровни. Если ни один не попадает (например, короткая горизонталь), используются её собственные вертикальные границы.

Компонент измеряет writing.getBoundingClientRect относительно строки, переводит каждый уровень из координат модели в CSS px и убирает совпадения. Поэтому появляются непрерывные горизонтальные линии через поля и промежутки, отдельные наборы линий после flex-переноса, без линий в зоне процентов. Измерения инициирует ResizeObserver строки и полей, сгруппированные через requestAnimationFrame. При удалении строки/перестроении листа наблюдатели и ожидающий кадр освобождаются.

Направляющие — CSS-слой ::before, растянутый inset:0 по строке, pointer-events:none. Он выше фонов оформления, но ниже SVG-подсказок, canvas и контролов. Толщина 1 CSS px, цвет учитывает пять оформлений. Старые короткие SVG-линии по minY/maxY и фиксированная разлиновка на 25/75% удалены, как и прежняя линия-разделитель под процентами разминки. Наклонных направляющих не добавляется.

Проверены уровни, масштаб 30/60/118/160, дублирующиеся поля и два физических ряда после переноса, неизменность данных и очистка наблюдателей. Статическое превью на основе актуальной SVG-геометрии и вычисленных координат — concepts/assets/horizontal-ruling-preview.png; это иллюстрация разлиновки, а не снимок реального браузера. Полная браузерная раскладка/Pencil инструментом не подтверждены.


## Прежняя учебная последовательность (сборка 14, заменена сборкой21)

Порядок не алфавитный. Отдельный LetterCurriculum хранит рабочую последовательность из ранее использованного источника:

```text
А У О Э И Ы М Н Л Р Е Ё Я Ю Ь Г К З С Д Т В Ф Б П Й Ж Ш Ч Щ Х Ц Ъ
```

Источник: [рекомендуемые модели планирования Молдовы, русский язык и литература, 2019–2020](https://edu.gov.md/sites/default/files/russkiy_yazyk_i_literatura_1-4_klass.pdf), букварный период, печатные страницы 4–7. Этот порядок подтверждён в исходном PDF повторно; первоначально он уже содержался в соседнем проекте 10-kids-alphabet/site/src/copybook-pages.mjs. Это исторический учебный ориентир, не действующая обязательная программа и не последовательность из ГОСТ. Упоминавшийся пользователем казахстанский источник в найденных материалах не подтверждён. Отдельный сохранённый разбор советского букваря 1952 года охватывает только начало и имеет другую последовательность; его не смешиваем с полной моделью.

Принцип страницы: элементы текущей формы → отдельные заглавная/строчная → буквосочетания/слоги → слова → предложения. Сложность наращивается через знакомые движения и накопление изученных букв. Форма движения берётся из нашего GOST B upright, школьные соединения/неотрывность из прописей не переносятся. На ранних страницах разделы слов/предложений могут отсутствовать: повтор ААА — только повтор буквы.

API: order, lesson(letter), knownLetters(letter), canUseText(letter,text), firstPractice(letter). Урок включает текущую букву и предыдущие, но не будущие. Небольшие авторские примеры демонстрируют проверку (ау после У; мама после М; Мама мыла раму после Р), не являются извлечёнными заданиями источника и не означают наличие готовых уроков/контуров этих букв.

`LetterSequence.normalizeText(text,{lesson,supported})` теперь проверяет две независимые вещи: допустимость букв для этого урока и наличие поддерживаемой геометрии. Даже готовый контур М не разрешит «мама» на уроке А. В текущем прототипе lesson=А, supported=Аа; новые уроки и навигация по всем буквам не реализованы этой правкой. Данные порядка приготовлены для их добавления, не открывают пустые/непроверенные страницы. Новая текстовая строка на А берёт простое повторение ААА из курса вместо произвольного чередования регистра; прежние составы и черновики не меняются.

Тесты проверяют все 33 буквы ровно один раз, учебный префикс, предыдущую/следующую букву, допустимость примеров, запрет будущих букв и отдельное ограничение доступной геометрии. Прежние сценарии редактора/разлиновки/сохранения проходят.


## Полный алфавит и LAN, сборка 15

- glyphs.js — единый реестр 66 кириллических контуров и пяти знаков. outline извлечён из TTF; model задаёт педагогическую траекторию; inkBounds ограничивает viewport, revision версионирует геометрию.
- letter-references.js — слово и путь локальной иллюстрации для каждой буквы. Само слово может содержать ещё не введённые буквы: оно служит иллюстрацией звука/буквы. Ограничение известными буквами применяется к тексту для письма.
- setLetterSources(sources, letter) — перенастраивает каталог по выбранной паре. Для А/а оставлены пять прежних частей с их ID. Другие страницы используют части собственных траекторий; точки диакритики группируются.
- build(variant, letter) сохраняет предыдущий урок, меняет геометрию и состав страницы, восстанавливает записи выбранной буквы. Последний выбор запоминается. Шкалы настроек общие.
- А сохраняет letter-worksheet-v3-<variant> и letter-page-composition-v1. Другие уроки используют letter-worksheet-gost-<codepoint>-<registryRevision>-<variant> и letter-page-composition-v2-<codepoint>. Версия всего реестра защищает также слова из предыдущих букв. Старые ключи не удаляются.
- LetterSequence.compose поддерживает maxWidth и lineAdvance=170 (17d). Слова переносятся целиком. В модели все буквы получают x/y, направляющие повторяются по строкам. При смене ширины повторно строится раскладка; при активном пере пересчёт откладывается. - Сборка 16: слово, которое само шире доступной строки, переносится между буквами без изменения масштаба. Помещающиеся слова по-прежнему переносятся целиком. Строки имеют min-width:0/max-width:100%, чтобы ширина одного задания не расширяла весь grid.
- Одиночное касание поддерживает точки Ё/ё и пунктуацию; оценка остаётся геометрической, без проверки направления/порядка.
- concepts/server.mjs — статическая LAN-раздача без API и внешних ресурсов. Сервис и хранение описаны в PROJECT.md.

Траектории новых букв получены из скелета точного контура; М/м и Х/х имеют явные центральные маршруты, А/а сохраняют одобренные маршруты. Это не утверждение нормативного или педагогически аттестованного порядка письма. Для будущей ручной правки маршрутов использовать route-overrides.json, затем регенерацию и растровый регресс; не править форму ГОСТ ради удобства маршрута.

Сборка 16: короткую полилинию можно делить на отдельные упражнения только при длине каждой стороны от 12 единиц. Мелкие соединители скелета остаются внутри полного маршрута; объединённые упражнения имеют route-v2 ID и legacyIds для переноса выбора. Если выбран хотя бы один прежний фрагмент, включается целый маршрут с прежним числом повторов первого выбранного фрагмента. Если все фрагменты были исключены, маршрут остаётся исключённым. Чернила прежних фрагментов не удаляются и не накладываются на маршрут.

Сборка19: необязательное поле glyph.demonstration задаёт порядок/центральный маршрут показa в тех же координатах. demonstrationFor возвращает его или glyph.model. Маска всегда раскрывает тот же glyph.outline; model остаётся источником проверки, подсказок и тренировочных частей. Исправление педагогического старта без изменения формы оценки не меняет её revision и не архивирует пользовательские записи. Маршруты показa авторятся в references/isopromat-fonts/demonstration-routes.json и проверяются tests/demonstration.test.cjs на промежуточную/полную растеризацию и часы.

Сборка20: LessonPictures.lessons[letter] содержит ids подходящих упражнений и parts с обоснованием по штрихам; forLesson(letter,variant) выбирает вариант.
