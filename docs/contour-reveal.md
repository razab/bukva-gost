# Раскрытие чертёжной буквы по движению карандаша

Статус: рабочее решение подтверждено пользователем 29 октября 2026 года после исправления стыков перекладины «А». Реализация находится в `concepts/index.html`. Это зафиксированный вариант для дальнейшего развития.

## Поведение

На одном листе показываются заглавная А и строчная а. Сначала рисуется заглавная, через 500 мс после её окончания — строчная. Готовые буквы остаются видимыми ещё 1000 мс, после чего цикл повторяется. Начало письма пользователя не останавливает анимацию. Кнопок воспроизведения нет.

Внутри буквы соседние линии с общим концом и началом показываются непрерывно. Между раздельными движениями карандаш поднимается на 420 мс. Это учебная последовательность прототипа: сам ГОСТ задаёт форму, а не педагогический порядок движения.

## Что задаёт форму

Используется **GOST type B Regular, тип Б без наклона**, файл ASCON из архива по ссылке пользователя: https://isopromat.ru/files-for-download/fonts-gost.

`references/isopromat-fonts/SOURCE.json` хранит точный источник, имя файла, SHA-256 и авторские сведения. SVG-контуры двух глифов извлечены из TTF без ручного перерисовывания. Их задаёт `fontOutlines`. Контур отображается через `fontOutline()` с масштабом 100/1400 и переносом (30, 140).

Отдельные центровые полилинии `models` и `lowercase` задают путь карандаша и геометрическую оценку пробы. Они не заменяют видимый контур: анимация открывает именно силуэт из шрифта. В TTF нет готового учебного порядка штрихов; центровые траектории — отдельные авторские данные.

Файлы шрифта исследованы для локального прототипа. В архиве не найдена явная лицензия на распространение; право включения в приложение App Store ещё не установлено. Значение fsType=0 не заменяет лицензию.

## Почему простая маска не сработала

Было две независимые ошибки.

1. **Разные системы координат.** Маска в координатах листа 150 × 180 применялась к пути, который ещё находился в шрифтовых координатах. Она почти не пересекала букву. Снятие маски в конце скрывало ошибку: карандаш уже прошёл, и только тогда буква заливалась целиком.
2. **Слишком широкая кисть.** После исправления координат кисть шириной 18 при толщине буквы около 10 захватывала соседние будущие элементы. У перекладины появлялись преждевременные пятна и ступеньки. Проверка только полного покрытия готовой буквы этого не обнаруживала.

Не возвращать снятие маски в последнем кадре и не исправлять неполное покрытие простым увеличением ширины кисти.

## Текущий алгоритм

### 1. Единая шкала времени

`demoClock()` вычисляет накопленные длины отрезков каждой полилинии. Скорость равна 84 единицам листа в секунду. Прогресс и положение карандаша вычисляются из одного расстояния; плотность точек на кривой не меняет скорость.

`sequenceClock()` объединяет оба регистра в один цикл. Только один карандаш активен в каждый момент. Межбуквенная пауза 500 мс отсчитывается от фактического завершения заглавной, без дополнительных стартовых задержек.

### 2. Принадлежность участков контура движениям

`revealRegions()` разбивает плоскость листа на области ближайших точек траектории:

- каждое движение пересэмплируется примерно через одну единицу длины;
- каждая точка получает номер движения и прогресс внутри него;
- повторное посещение той же точки ближе 0,025 единицы сохраняет принадлежность первому посещению;
- для каждой точки строится ячейка Вороного отсечением прямоугольника листа полуплоскостями конкурентов;
- результаты кешируются в WeakMap по модели.

Каждая область открывается, только когда карандаш достиг её прогресса. Так будущая перекладина не появляется от широкой кисти, проходящей по соседней наклонной стороне. Принцип взят из `stroke-reveal.mjs` существующего проекта прописи и адаптирован к этому листу.

### 3. Непрерывное ядро штриха

Дополнительно маска содержит движущийся штрих толщиной 10. Он сохраняет непрерывность уже пройденной линии в стыках и пересечениях. Его длина раскрытия равна пройденному карандашом расстоянию. При нулевом прогрессе штрих невидим, чтобы круглый конец не оставлял точку до начала движения.

Видимые области маски имеют белую обводку 0,12 единицы, уменьшающую швы растеризации между соседними ячейками. Эти значения подобраны для текущего масштаба и типа Б; для других размеров/шрифтов их нужно проверять заново.

### 4. Маска в координатах листа

SVG устроен так:

```xml
<defs>
  <mask maskUnits="userSpaceOnUse" maskContentUnits="userSpaceOnUse">
    <!-- области траектории и её непрерывное ядро -->
  </mask>
</defs>
<g mask="url(#mask-id)">
  <path transform="translate(30 140) scale(s -s)" d="исходный контур TTF" />
</g>
```

Маска находится на внешней группе. Преобразование шрифта — внутри неё. Карандаш, маска и часы движения используют координаты листа.

Маска остаётся включённой даже в полностью готовой букве. Нет финального переключения, которое могло бы скрыть непрорисованные области.

### 5. Обновление кадра

`revealMarkup()` строит исходный SVG. `playDemo()` меняет видимость только тех областей, чей статус изменился, длину ядра и положение карандаша. Геометрия областей не пересчитывается каждый кадр. При смене оформления прежний requestAnimationFrame отменяется, затем запускается один новый цикл.

## Проверенные свойства

- Цвет появляется под карандашом уже во время первого движения.
- Готовая линия не исчезает при раскрытии следующего штриха.
- Наклонные стороны А непрерывны в местах соединения с перекладиной.
- Середина перекладины не закрашена до начала её движения.
- Контур готовой буквы покрыт более чем на 99,5% относительно растеризации исходного глифа.
- Между 99,9% последнего движения и готовым состоянием нет заметного скачка заливки.
- Готовая заглавная остаётся видна при показе строчной.
- Цикл, сбросы, отмена и сохранение пользовательских проб продолжают работать.

## Как проверить

Из корня проекта:

```sh
node concepts/tests/worksheet.test.cjs
RESVG_MODULE=/путь/к/@resvg/resvg-js node concepts/tests/reveal-render.test.cjs
```

Первый тест выполняет код настоящей страницы в моделируемом DOM. Второй использует SVG-растеризатор resvg и проверяет реальные пиксели промежуточных кадров. Если @resvg/resvg-js установлен обычным способом и доступен Node, переменная RESVG_MODULE не нужна. Зависимости тестового инструмента не требуются странице для работы.

Иллюстрации проверок:

- `concepts/assets/junction-reveal-check.png` — шесть стадий перекладины после готовых сторон;
- `concepts/assets/upright-reveal-check.png` — историческая проверка исправления координат маски до доработки стыков; не эталон текущего разделения областей.

Пользователь подтвердил работу текущего результата. Это не означает, что отдельно проверены Apple Pencil, жесты, производительность на iPad или все будущие буквы.

## При добавлении букв

Для каждого нового глифа брать настоящий контур выбранного файла, отдельно задавать учебные движения и проверять отрывы. Проверять промежуточные состояния у всех стыков и пересечений, а не только итоговую форму. Сравнивать реальную растеризацию с контуром и следить, чтобы следующие штрихи не стирали предыдущие. Прохождение проверок А/а не подтверждает остальные буквы автоматически.
