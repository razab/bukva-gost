# Design

## Context

Runtime56 — веб-приложение. Есть readBundle в scripts/internal-package.mjs, SOURCE.json шрифта, выпускные документы и три тестовых уровня. Нативной поставки нет; LetterDrawing/ — старый эксперимент. Четыре локальные правки правил предварительного согласования уже существовали до этого change и не являются реализацией нового аудита.

## Goals / Non-Goals

Основной вход — один вызов `$apple-preflight` в текущем Codex. Внутри он получает механические факты и дополняет их аудитом. Это запуск агента по запросу, не автономная cron-задача. Его AI-часть использует текущую сессию и её обычные лимиты; отдельные ключи/платные AI API и дочерние AI-процессы не нужны.

Скрипт отдельно пригоден для терминала/CI, но без вывода модели не оценивает смысл продукта. В этой редакции он не разбирает .xcarchive и не проверяет подпись: эти строки остаются в отчёте. Подключение нативного адаптера согласуется после появления выбранной упаковки.

## Decisions

### Один внешний checklist и проектный вход

После одобрения установить safaiyeh/app-store-review-skill v1.5.0 в проектные dev-skills из commit7197cff003728b660542b37d6b6d0167fe2ec1ed, сохранив MIT и источники. Прочитать полный загружаемый набор перед использованием. Проектный apple-preflight задаёт режим только аудита, последовательность запуска и формат. Пример внешнего skill не является командой добавлять push, биометрию, регистрации или покупки.

Три пакета одновременно не устанавливать: они перекрываются, некоторые правила слишком категоричны. От chingiz/appstore-preflight полезен формат доказательств/непроверенного; его скрипты не подходят текущему проекту без Xcode-артефактов. При содержательном аудите сверять применимые пункты с официальной Apple-документацией; записывать URL и дату проверки. Нет доступа к актуальному источнику — явно указать ограничение.

### Техническая команда

`npm run check:apple` читает исходники и существующий dist/web/, не пересобирает их. Переиспользовать readBundle; дополнительно сверять ресурсные байты с текущими исходниками, включая нормализованную offline-обёртку index.html. Не дублировать весь сборщик ради проверки HTML.

Механические пункты: целостность/актуальность комплекта, допустимые пути, реально включённые dev-ресурсы, наличие записанного происхождения ASCON/PNG. Отсутствие комплекта — UNKNOWN, повреждённый/устаревший комплект — BLOCK, наличие dev-панели — FLAG для выбора состава Release, не автоматический приговор Apple. Неизвестные права — UNKNOWN, без юридического вывода. Privacy/Support URL, родительские барьеры, сетевое поведение, содержание и самостоятельная ценность анализируются агентом с указанием фактических файлов/экранов; поиск строки не доказывает поведение.

Exit0 означает только завершённые доступные механические проверки без BLOCK; exit1 — найден BLOCK; exit2 — ошибка/недостаток обязательного входа команды. Сводка отдельно показывает неполноту всего аудита. Успешный exit0 не называется разрешением на отправку.

### Сохранение доказательств

Отдельный reports/apple-review/<run-id>/ содержит mechanical.json и объединённые report.json/report.md. Сохранять исходные факты скрипта: агент добавляет семантические результаты, не переписывает выполненные проверки. Проверка формы отчёта отклоняет неизвестные статусы, пропущенные обязательные разделы, противоречие техническому результату и fingerprint другого входа. Записывать build, Git HEAD, хеши проверяемых исходников/артефактов, версию skill и время.

Непроведённые подпись, физическое устройство и App Store Connect остаются видимыми. Отсутствие покупок/логина обосновывает N/A; отсутствие нативного пакета не обосновывает N/A для подписи будущего App Store-приложения.

### Проверки реализации

Расширить существующий offline-bundle через небольшой helper; не создавать новый тестовый уровень и не запускать full внутри каждого аудита. Сквозной canary после одобрения: здоровый комплект → технический JSON → аудит по skill → читаемый отчёт; затем повреждённый ресурс/отсутствующий комплект и повторный запуск с изменённым входом. Сверить, что защищённые входы и LAN не изменились. Только после этого полный реальный отчёт по текущему проекту и medium.

## Risks / Trade-offs

- Семантический аудит зависит от модели → отдельная маркировка автора вывода, конкретные доказательства и обязательные UNKNOWN/NOT_CHECKED.
- Внешний checklist может устареть или содержать расширительное толкование → фиксированный commit, сверка с Apple, без автоматических обновлений/auto-fix.
- Пользователь примет зелёные механические пункты за общую готовность → сводка неполноты, список неисполненных проверок и точное значение exit-кода.
- Реального нативного пакета нет → не обещать проверенную подпись/SDK/privacy manifest и не моделировать её успешной fixture-папкой.

## Migration Plan

Миграций работ, настроек, геометрии и пользовательского UI нет. Dev-skills и отчёты остаются вне LAN/offline-комплекта. Откат затрагивает только новые dev-файлы/команду; номер56 и хеш автономного приложения сохраняются. Одобрение предложения не является одобрением исправления обнаруженных продуктовых рисков: для них показываются отдельные изменения.
