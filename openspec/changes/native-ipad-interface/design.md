## Основания и сравнение

| Сейчас | Изменение |
|---|---|
| Фиксированный HTML-хедер и ряд рамочных кнопок | SwiftUI toolbar, системные кнопки/SF Symbols и компактное Menu |
| HTML dialog занимает почти экран | Системная sheet с NavigationStack, закрытием, прокруткой и жестом dismiss |
| Веб-карточки и техническая форма | Нативные Grid/List/Form, Picker/Toggle/Slider |
| Внешне iPad, данные/контролы живут только в странице | Узкий мост команд/снимков состояния, один источник данных в существующем движке |

Для тренажёра важнее ширина листа, чем постоянная навигационная колонка.
Не добавляем постоянный sidebar или лишние вкладки. Технический редактор состава
допустим как отдельный авторский экран, но не заменяет нативные пользовательские настройки.

Мост не передаёт raw ink на каждом движении. Состояние обновляется по окончании
действия; каталог/журнал читаются при открытии. Параметры передаются через
callAsyncJavaScript arguments. Slider коммитится при отпускании. SVG-демо использует
исходную реализацию анимации, навигационные изображения букв — контуры ГОСТ.

## Canary и защита
Сначала нативный toolbar → выбор другой буквы → настройка → письмо/undo →
перезапуск с теми же данными и реальный снимок. После него остальные окна и Files.
Отдельная QA-копия сохраняет пользовательские работы. Основной пакет обновляется
только после проверки ресурсов, подписи, обеих ориентаций и файлового цикла.

Второй проход: объём соответствует запросу iPad UI, требования проверяемы;
новые игровые механики, шрифты, оценка и схема хранения не входят.

## Проверки
Первый native-canary на симуляторе прошёл: каталог → О → выбранная сложность →
отдельное динамическое демо → перезапуск с О. Скриншоты просмотрены.
В полном прогоне прошли 8/9: движок/все уроки/данные и нативные Files,
настройки, авторский редактор, результат, журнал. Жест рисования не был принят;
запись показала прокрутку, а в SQLite отсутствовало изменение режима ввода.
Тест переключателя уточнён: нажатие по самому UISwitch справа и обязательная
проверка значения 0 до жеста. Не считаем нажатие по надписи успешной сменой.

Физический iPad стал недоступен в CoreDevice до запуска новой проверки.
Владелец получил запрос подключить устройство; программные проверки продолжаются
на симуляторе. Это не аппаратный PASS новой версии.

### Диагностика Slider и touch targets
Проверка всех ползунков выявила реальное расхождение: на экране/в AX отступ18,
а обработчик окончания передавал19, что подтвердил временный native log.
Уточнение зоны прокрутки не устранило ошибку; дальнейшие массовые повторы
остановлены, добавлен отдельный canary одного отступа с перезапуском.
Передача draft из SwiftUI end callback оказалась нестабильной; перенос на main
queue/onChange не устранил расхождение. Этот подход остановлен. UISlider теперь
передаёт собственное финальное значение по touch-up, с округлением к шагу и
границам; valueChanged во время tracking только обновляет превью. Изменения через
accessibility без tracking применяются сразу. Временное логирование удалено.
Минимальный canary одного отступа после этой замены прошёл (uikit-slider-canary).
Тесты сравнивают точное значение до/после перезапуска, без послабления допуска.

Стандартное преобразование toolbar Label в UIKit давало AX frame36pt, несмотря
на frame44 у label. Для этих toolbar-кнопок использован системный plain style
с frame44; Menu получает menuStyle(.button), чтобы использовать тот же размер.
Обычные Form/Picker не получают эту стилизацию. Проверяются реальные AX frames
в двух ориентациях, письмо/undo и независимость действий.

### Поворот и границы доказательств
Просмотр снимка выявил ложноположительную старую проверку: XCUIDevice.orientation
изменялся, но фактическое окно оставалось834×1210. После добавления ожидания
реального aspect тест перестал проходить. Запрос UIWindowScene отклонён ОС:
«The current windowing mode does not allow for programmatic changes to interface
orientation». Не исправляем приложение принудительным поворотом ради теста.

Вместо этого testNativeLayoutSizes задаёт bounds действующего UIKit-компонента
1210×834/834×1210, ждёт и UIView, и фактический innerWidth WebKit, проверяет
отсутствие горизонтального overflow и неизменный raw ink, сохраняет снимки.
Первый слишком ранний снимок/проверка не ждали WebKit resize; явное ожидание
viewport устранило эту ошибку теста. Это проверка размеров, а не физический поворот.
Поворот выделен в testPhysicalLandscapePresentation: simulator lane явно SKIP,
на устройстве требуется реальный широкий frame. Окно объявлено через стандартный
Scene manifest, без нескольких одновременных писателей в общее хранилище.

Для круглого системного Menu проверяются середины левого/правого краёв круга,
а не углы ограничивающего квадрата. Кнопки с прямоугольным target имеют явный
contentShape. Верхние действия/закрытие проверяются по краям отдельно от center.
Mac заблокирован (CUA), iPad отключён; запрос владельцу отправлен. Не выдаём
ограничение стенда за подтверждённую аппаратную приёмку.
